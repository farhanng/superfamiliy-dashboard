## 3. Issues Found

1. **`oauth_enabled: false`** in `/health` — Backend health endpoint shows `oauth_enabled: false`. The OAuth flow still works at the API level, but this flag should likely be `true` for consistency if the feature is intended to be fully enabled.

2. **Google OAuth error on click** — When clicking the Google OAuth button, the flow redirected to:
   ```
   https://accounts.google.com/signin/oauth/error?authError=Cg9pbnZhbGlkX3JlcXVlc3Q
   ```
   This `authError=Cg9pbnZhbGlkX3JlcXVlc3Q` error (base64 for `invalid_request`) may indicate:
   - The `state` parameter or `code_verifier` has an encoding issue
   - Or a known Google OAuth error for the "invalid request" generic error
   - **Note:** This was captured in automated test but could also be a test environment artifact

3. **TC-DASH-04 (Language toggle)** — The `#lang-toggle` element was not in viewport during test. Test still passed because it fell back to checking the Google button presence. Not a failure, but the toggle may not be visible on mobile viewport (390×844).

---

## 4. Recommendations

1. **Set `oauth_enabled: true`** in the backend config/production environment. This is the most likely source of the `oauth_enabled: false` flag, which may affect other OAuth-related behaviors.

2. **Investigate Google OAuth `authError=invalid_request`** — The backend generates a PKCE `code_challenge` and `state` parameter. If Google returns `invalid_request`, check:
   - That the redirect URI registered in Google Cloud Console matches exactly `https://superfamily-backend-916992190881.asia-southeast1.run.app/api/auth/google/callback`
   - That the `state` parameter is being properly passed through the redirect chain

3. **Whitelist check behavior** — Not yet tested end-to-end. The existing `sso-login.puppeteer.cjs` does not test invalid email rejection or whitelist enforcement. A dedicated test case (e.g., `TC-SSO-04: Invalid email rejected by whitelist`) should be added to cover:
   - An email not in the whitelist attempting to log in
   - Expected rejection/error message

4. **Full OAuth flow end-to-end** — The test suite does not currently perform the full callback handshake. The TC-SSO-02 test clicks the OAuth button but doesn't complete the Google sign-in + callback + token exchange + dashboard redirect cycle. A full E2E OAuth test would require a test Google account and would validate the complete PKCE flow.
